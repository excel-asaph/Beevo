Great question! This is exactly the kind of "Generative UI" feature that would differentiate your project. Let me explain the options:

🌐 Generative UI Options for Your Canvas
Option 1: Embedded Live Preview Node (Recommended)
Create a new node type called PreviewNode that contains an iframe or a sandboxed HTML renderer. When Gemini generates a landing page, you inject the HTML/CSS directly into this preview.

How it works:

User: "Create a landing page for my brand"
    ↓
Gemini generates HTML/CSS/JS string
    ↓
Server sends `PREVIEW_UPDATE` message to client
    ↓
PreviewNode renders the HTML in a sandboxed iframe
Technical Implementation:

Use an <iframe srcDoc={generatedHTML}> inside a ReactFlow node
The iframe is sandboxed (sandbox="allow-scripts") for security
The node can have "Edit", "Deploy", "Regenerate" buttons
Pros: Fast, runs in-browser, no external dependencies
Cons: JavaScript execution is limited in sandbox

Option 2: Sandpack Integration (Code + Preview)
Use Sandpack (by CodeSandbox) - it's an embeddable code editor with live preview, specifically designed for this.

How it works:

User: "Build me a React landing page"
    ↓
Gemini generates React component code
    ↓
Sandpack node shows code editor on left, live preview on right
    ↓
User can tweak code, preview updates in real-time
Pros: Full React/JS support, code editing, feels like a real IDE
Cons: Heavier bundle, more complex setup

Option 3: Server-Side Screenshot (Puppeteer)
For situations where you need a static preview or the generated page is complex:

How it works:

Gemini generates HTML/CSS
    ↓
Server uses Puppeteer to render the page headlessly
    ↓
Puppeteer takes a screenshot (PNG/WebP)
    ↓
Server sends image back to client
    ↓
ImageNode displays the screenshot
Pros: Works for any website, looks pixel-perfect
Cons: Slower, not interactive, requires Puppeteer on server

Option 4: External Browser Window (Agent Style)
The most "Agentic" approach, like what Google Antigravity does:

How it works:

User: "Create and test a landing page"
    ↓
Agent spawns a real browser window (via Puppeteer)
    ↓
Agent writes code, opens the page in browser
    ↓
Agent takes screenshots at each step
    ↓
Agent clicks buttons to "test" the page
    ↓
Agent reports back: "The signup button works, but the font is off"
Pros: TRUE agentic behavior, judges will love this
Cons: Complex orchestration, requires background process management

🎯 My Recommendation for Your Project
Given your hackathon context and time constraints, I recommend:

Phase 1 (Quick Win): PreviewNode with iframe
Create a LandingPageNode.tsx that renders an iframe
When the AI generates HTML, pipe it into srcDoc
Add a "I like it" button that saves to Brand Vault
Phase 2 (Wow Factor): Show the AI "thinking" about the page
Before showing the preview, show a Thought Signature:
"Based on your brand voice 'Bold and Empowering', I'm using a hero section with high-contrast CTA buttons. Your primary color #FF5722 is applied to conversion elements."

Phase 3 (Agentic): Self-Verification Loop
After generating, the agent "reviews" its own output:
"Checking... ✓ Logo is in safe zone, ✓ Brand colors match DNA, ⚠️ CTA button contrast ratio is 3.8:1 (needs 4.5:1). Regenerating..."
